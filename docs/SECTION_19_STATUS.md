## 4. What is genuinely unfinished, and what closes each item

1. **The 1.1.0 UI has been compiled but never run.** Compilation is now proven (CI #11), and
   the three SDK-level mistakes it caught are fixed; but no v1.1.0 screen has executed on
   hardware.
   → sign and install the IPA, then run `DEFINITION_OF_DONE.md` §3.
2. **Live provider / OAuth / integration sends have never run with a real credential.** →
   your key in Settings ▸ AI Providers, then **List models** and **Run test**; OAuth per
   `docs/INTEGRATIONS.md`. No credential is required for anything else here, and none is stored.
3. **The provider fix itself needs one confirmation on your phone**: after "Save key and
   activate", the Active-provider card must name the provider you chose, and "Run test" must
   return a green banner or a Diagnostics block that says why.
4. **On-device behaviour is unverified** (face animation, haptics, VoiceOver, Dynamic Type,
   Reduce Motion, notification delivery) — the same checklist, about ten minutes.
5. **CI found four real defects and is green now.** The four red runs are kept in the
   record (`docs/TEST_REPORT.md` §6): a test only a different toolchain rejected, an
   unreadable project file, a missing `import UIKit`, and a relative-path bug in the
   packaging script.

## 5. What this report deliberately does not say

* It does not say "zero errors". `DEFINITION_OF_DONE.md` §5 lists **fourteen** real defects
  found by running things rather than by review — among them a dropped SSE final event,
  stop-word retrieval noise, a `weak` reminder engine that silently became `nil`, transcript
  truncation before compaction, a `ConfirmationBroker` race, a `6pm` parse bug, a quota error
  wrongly marked non-retryable, an empty first `project.pbxproj`, icon blur halos, a test
  runner that hid the pytest count, the provider-settings bug your phone found, the tab bar
  that covered its own buttons, a lip-sync shape that read the first letter instead of the
  vowel, and three SDK-level mistakes that only Xcode could catch (`state == .failed` on a
  payload-carrying case, a missing CoreMotion queue argument, `nil` for a non-optional queue).
* It does not claim the 1.1.0 UI has been *run*. It has been compiled and linked (CI #11);
  nothing from it has executed on hardware yet.
* It does not claim any integration works against a live service. Every such test is
  labelled **mocked** in `TEST_REPORT.md`.
